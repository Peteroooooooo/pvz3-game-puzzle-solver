# PVZ3 文案审查与替换建议

> 原则：尽量使用中性、简洁、可翻译的产品文案。  
> 不把二次理解写成“官方原话”。如果没有官方公开文本，就用直译式、功能式表达。

## 1. 总体问题

- 现在有一部分文案偏口语化，比如“最强”“真·全真”“风控”“废料”“加料喷溅”。
- 有一部分文案带明显主观解释，比如“实机此时会…”“恶劣动态加料下的真实通关能力”。
- 有一部分文案像内部调试语言，不适合公开页面，比如“蒙特卡洛”“压测”“续推”“死锁淘汰”。

建议统一成三种语气：

1. 标题层：`PVZ3 Game Puzzle Solver`
2. 功能层：`Refill-Aware A*` / `Puzzle Solver`
3. 说明层：`Simulate refill after recipe clear`

## 2. 高优先级替换

| 当前位置 | 现在的写法 | 建议写法 |
|---|---|---|
| 页面标题 | `PvZ 3 杀虫剂调剂大师 · 试管最优解推演器` | `PVZ3 Game Puzzle Solver` |
| 主标题 | `PvZ 3 杀虫剂调剂大师` | `PVZ3 游戏谜题求解器` / `PVZ3 Game Puzzle Solver` |
| 副标题 | `BUG SPRAY BARISTA · OPTIMAL SOLVER` | `REFILL-AWARE WATER SORT · A* SEARCH` |
| 主按钮 | `推演最优解` | `求解最短路径` / `Solve` |
| 随机加料 | `随机加料` | `模拟加料` / `Simulate Refill` |
| 示例关卡 | `经典固定关卡` | `示例关卡` / `Sample Puzzle` |
| 冒烟测试 | `100 局自动化对抗冒烟测试` | `100 局模拟测试` / `100-run simulation` |

## 3. 说明文案替换

| 当前位置 | 当前表达 | 建议表达 |
|---|---|---|
| 方案卡说明 | `将为您规划最快消除指定配方并防止死锁的最优倾倒序列` | `系统将规划达成目标配方的倾倒路径，并在加料后支持继续求解` |
| 测试说明 | `恶劣动态加料下的真实通关能力` | `在动态加料条件下评估成功率与平均步数` |
| 结果通知 | `真·全随机关卡生成成功` | `随机关卡已生成` |
| 结果通知 | `最强档` / `风控路径` | `加料感知路径` / `refill-aware path` |
| 结果通知 | `废料` | `加料格数` / `refill units` |
| 结果通知 | `死锁` | `无可行解` / `stuck state`（公开页面建议用前者） |

## 4. 建议统一的术语

| 中文 | 英文 |
|---|---|
| 谜题 | puzzle |
| 求解器 | solver |
| 倒水 | pour |
| 加料 | refill |
| 盘面 | board |
| 目标配方 | target recipe |
| 自由中转瓶 | buffer tube |
| 示例关卡 | sample puzzle |
| 最短路径 | shortest path |
| 物理合法 | physically valid |

## 5. 不建议保留的表达

- `最强`
- `真·`
- `风控`
- `压测`
- `废料`
- `续推`
- `杀虫剂调剂大师`

这些词不适合公开页面首页，也不利于搜索。

## 6. 双语落地建议

先做两层：

1. 首页和 README 双语
2. 主要交互文案双语

再做完整 i18n：

- 用一个 `i18n` 字典统一管理按钮、提示、标题
- `?lang=zh` / `?lang=en` 切换
- 页面标题、按钮、提示、通知统一从字典读取

## 7. 结论

如果目标是“更专业、好搜、像一个正式项目”，推荐把首页口吻统一成：

- `PVZ3 Game Puzzle Solver`
- `Refill-Aware A*`
- `Static browser puzzle tool`

这样最稳，也最适合 GitHub Pages 和中英双语。

# PVZ3 游戏谜题求解器

这是一个面向 **Plants vs. Zombies 3** 的静态网页谜题工具，重点覆盖倒水求解、加料模拟和反馈推演。

在线演示：[https://peteroooooooo.github.io/pvz3-game-puzzle-solver/](https://peteroooooooo.github.io/pvz3-game-puzzle-solver/)

## 仓库内容

- `pvz3_water_sort_solver.html` - 支持实机加料规则的倒水求解器
- `water_solver_engine.js` - 可测试的最短路、满瓶屏蔽与随机加料策略核心
- `water_solver_worker.js` - 浏览器后台求解 Worker
- `water_image_engine.js` / `water_image_worker.js` - 按需运行的本地截图识别
- `water_image_import.js` / `water_image_templates.js` - 截图预览、校正与轻量配方参考
- `seeded_simulation_test.js` - 固定补料种子的可复现策略 A/B 测试
- `pvz3_decode_solver.html` - 配套的解码 / 反馈推演工具
- `assets/pvz3/` - 页面使用的本地素材

## 特点

- 支持 PVZ3 风格的完成后加料机制
- 支持选择、直接拖入页面或粘贴本地 PNG、JPG、WebP 截图，识别七瓶液体与配方，核对后载入盘面；可裁剪重试、直观修改结果和撤销导入
- 截图提取的真实配方图标、倒出／接收箭头、紧凑的手机布局与当前步骤栏；算法策略和搜索预算保持直接可选
- 满瓶屏蔽策略会单独保留可锁死加料的布局（尤其是恰好 4 个可接料瓶），再将其完整后续成本与立即清瓶及其他布局比较
- 静态模式使用完整状态搜索给出可验证的最短路线；测试示例由旧版 15 步降至已证明最短的 13 步
- 加料模式默认优先降低最坏总步数，同分再降低平均步数；分别显示最坏步数上下界、平均成本和剩余差距，只有上下界收敛时才标记全局最优
- 整局 25 步目标包括第四个配方完成前的三次随机加料，逐分支完整验证才显示保证；加料后复用已验证路线并扣除已走步数，在手机执行步骤后直接导入下一张截图也会累计整局步数
- 按整局剩余步数检查每个加料分支，逐步收紧已验证策略的上限；清瓶搜索可从原有队列继续展开，突破候选短名单。时间、节点和活动状态数量达到上限时保留原有方案
- 支持 4 秒、15 秒和 60 秒搜索预算，计算在 Web Worker 中执行
- 解码器默认严格反馈策略：全部 11,880 种不重复的合法真解，在正确槽位永久锁定时均保证 4 轮内完成
- 纯浏览器运行，无需安装
- 适合 GitHub Pages 静态部署

## 验证

```bash
node smoke_test.js
node water_solver_engine_test.js
node water_solver_optimization_test.js
node water_solver_worst_case_test.js
node water_solver_budget_search_test.js
node water_solver_batch_verify_test.js
node water_image_engine_test.js
node seeded_simulation_test.js
```

内置示例的 2,048 个固定补料种子测试中，所有策略均为 100% 通关。策略在第一次清瓶前多布局 1 步，留下恰好 4 个可接料瓶，把该次随机加料锁成唯一结果；平均为 16.800 步，观测最坏值为 17 步。相较平均 20.825 步、最坏 23 步的最快清瓶基线，平均减少 4.025 步（19.33%）。盲目追求更多满瓶护盾仍会升至平均 23 步，因此算法只会在完整后续成本确实更低时优先选择锁死加料。

最坏步数优先模式在上述示例中，完整验证了所选策略的 7 条不同加料边（8 个策略状态），最坏 17 步、精确期望 16.8 步。测试还通过 114 个小盘面的独立穷举最坏步数对照，以及 1,760 个静态最短路对照。剪枝使用各目标瓶必须移出的颜色段总数加最后一次清瓶作为下界，并用容量至多 4 的小规模动态规划计算取料与移除遮挡的最低成本；先检查困难加料分支，按已有策略上限限制清瓶搜索深度，并把剩余步数上限传入后续分支。页面只保留所选策略的状态，不传输和缓存未使用的搜索备选。

25 步保证覆盖当前盘面、三次随机加料的全部已建模分支及完整验证的策略。最近提供的五色、四配方截图已验证整局最坏 21 步。另生成 1,000 个不同初始盘面（四色、五色各 500，其中 500 个为底色错误且液体完全分段的困难配方布局），全部通过完整分支验证，最坏为 14～25 步；独立复核 11,607 个策略状态和 12,935 条加料边。发现并修复候选限制偏紧及缓存后续路线缺失的问题，补搜保持原有时间预算。最后一个配方完成后不再计算第四次加料。这些样本尚未构成所有初始盘面的全局证明；[验证报告与复现命令](./docs/water-budget-verification.md)提供逐局数据和生成种子。

本轮优化用默认 4 秒预算重测原记录中 125 个达到 25 步的盘面：15 个降到 23 步、92 个降到 24 步、18 个保持 25 步，全部通过完整加料分支复核，其中 104 个已证明最坏步数最优。另有 8 个三配方小盘面与独立穷举完全一致，同时验证恰好可行的预算和少一步时不可行的预算。

再用新种子生成 200 个盘面，沿用默认预算，全部通过三次加料的完整分支验证，最坏为 15～25 步；195 个在 24 步以内，88 个已证明最坏步数最优。逐局记录及复现命令见验证报告。

## 反馈推演器

先把显示的推荐组合填入游戏，再点选各槽位的实际反馈。提交按钮会指出尚未填写的反馈，填齐后生成下一轮推荐。点击基础卡牌可就近打开五张选卡面板。「撤回上一轮」恢复该轮卡牌、反馈、候选、游戏已确认的槽位、反馈规则和尝试次数。确定唯一答案后直接显示结果，不弹窗，也不再接受重复提交；游戏已确认的卡牌与推算答案分别标示。计算详情默认折叠，反馈冲突时自动展开。反馈按钮使用游戏截图预先提取的透明图标。

## 从截图导入

把静止的游戏截图直接拖到页面、粘贴图片，或点击「📷 图片导入」。桌面并排展示原图和七瓶预览，手机上下展示。点击某一层液体或配方即可修改该项。黄色项目需要核对，「请确认」项目需要选择明确值，然后点击「载入盘面」。识别失败时可拖动框选包含全部七瓶的游戏区域，松开后自动识别，无需再点「重新识别」。导入后手动求解，撤销可以恢复之前的配置。

顶部「随机加料」保留原来的加料行为。点击瓶子下方的真实图标可修改配方；100 局模拟测试位于「更多」。播放时间设置和完整步骤始终显示，策略说明和计算详情按需展开。五张透明配方图标均由截图预先提取，显示时不执行图像处理。

图片只在浏览器本地处理。工作图长边最多 960 像素，识别通过颜色分割、形态学闭运算、连通区域、瓶形归一化及五种配方的前景模板完成。液体识别扫描每层可见区域，按图片高光归一化亮度和色差，排除贴纸前景、液面与瓶底边缘，再结合逐行证据及自瓶底连续填充的整瓶模型；没有颜色证据的遮挡层保持待确认。配方轮廓断裂时，通过图标内部亮度纹理辅助校验，粗搜索保持小规模。浅色背景与白色瓶框相连时，最多追加两次不同对比度的候选提取，并保留原本完整的瓶框。没有视觉模型或新增依赖。HTTP / GitHub Pages 使用按需创建并终止的 Worker；直接打开 HTML 时使用同尺寸限制的本地回退。关闭预览后释放图片，闲置时不扫描。

识别测试使用提供截图的解码像素，并覆盖缩放、黑边、间距变化和亮度变化；这些是派生测试，不能代替不同手机的实机样本。现有瓶形以外的画面、动画和遮挡可能需要校正。未收录的贴纸可通过浅色轮廓包围的颜色识别，并标黄供核对；瓶内局部轮廓允许粉紫等轻度染色，避免葡萄贴纸漏识别。
